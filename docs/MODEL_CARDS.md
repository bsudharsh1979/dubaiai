## Hazard tool cards (versioned, deterministic)

### Water-balance twin — `water_balance_twin/0.3.0`  <a id="water-balance-twin"></a>

* **Method**: per-catchment, per-step mass balance. Inflow = rain × runoff × area + routed upstream spill (travel
  delay); outflow = drain capacity × (1 − blockage) + pump capacity × availability + mobile pump. Storage is
  bounded by `max_storage_m3` (spill routed downstream); depth = storage / storage area.
* **Invariant**: `assert_mass_balance` fails the run if |Δstorage − (in − out − spill)| exceeds tolerance.
* **Mechanisms**: `flash_flood` (short travel time, high runoff, fast rise) vs `waterlogging` (low-lying storage,
  drain-limited recession) — reported per catchment with a band (`low/moderate/high/severe`).
* **Horizons**: +30/+60/+180 min are **simulation horizons**, not forecasts.
* **Label**: `scenario model — uncalibrated`. Calibration status: none. Evaluation: not evaluated.
* **Controls**: rain multiplier, drain blockage, pump availability, extra mobile pump, sensor outage flags, report
  reliability (affects evidence, not physics).

### Sentinel-1 change screen — `sar_change_screen/0.2.0`  <a id="sar-change-screen"></a>

* **Validation**: same CRS, overlapping extent (>50 %), aligned grid (resampled with warning), dB units range
  check, nodata handling, matching relative orbit/direction/polarization, acquisition order.
* **Mask**: `after < WATER_DB` and `after − before < CHANGE_DB` → class 1 **candidate inundation at acquisition
  time**; permanent-water and shadow masks optional; ambiguous band → class 3 unknown.
* **Caveats** (emitted with every result): thresholds are a documented baseline; smooth surfaces (asphalt, sand)
  and radar shadow look like water; acquisition time ≠ decision time.
* **Evaluation**: `evaluation.harness.segmentation_metrics` computes IoU/precision/recall when a truth raster is
  supplied; **not evaluated** (no labelled UAE flood masks in this repo).

### Flow/pressure residual screen — `pressure_flow_residual/0.2.0`  <a id="residual-screen"></a>

Night-flow residual against a per-DMA baseline with pressure corroboration; outputs an anomaly band, competing
explanations (leak, planned flushing, meter fault, demand event) and `evidence_sufficiency`. Label:
`anomaly screen — uncalibrated`. Not evaluated.

### Asset exposure overlay — `asset_exposure/0.2.0`  <a id="asset-exposure"></a>

Buffer intersection between a hazard polygon and the asset register with criticality; carries the hazard label
through unchanged (observed / forecast / candidate).

### Constrained router — `constrained_router/0.2.0`  <a id="router"></a>

Dijkstra over the sector road graph with excluded links (closed / flooded / candidate inundation). Output is always
`candidate route — requires verification` or `no verified route`.
